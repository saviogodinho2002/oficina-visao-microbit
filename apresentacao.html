Por que no navegador e não em Python?

O caminho "clássico" quebrou

  • Tutoriais e a biblioteca cvzone usam mp.solutions.face_mesh do MediaPipe
  • Essa API foi removida no MediaPipe 0.10.30 (dez/2025); a versão atual é 1.x
  • Somando o detector de emoção (DeepFace), ficam 3 pacotes de OpenCV instalados ao mesmo tempo e o numpy troca de versão
  • Com máquinas Windows, Linux e macOS, a instalação vira o assunto da aula

No navegador

  • Só precisa de Chrome ou Edge e de um servidor local
  • Mesmo comportamento em qualquer sistema
  • Repositório escolhido: vladmandic/human (MIT): malha, íris, emoção, corpo, mãos, gestos
  • Os modelos e a biblioteca compilada vêm dentro do repositório: depois de baixar, roda sem internet
  • O navegador ainda fala com o micro:bit pela USB (Web Serial)

Preparação

# 1. baixar (só a versão atual, ~116 MB)
git clone --depth 1 https://github.com/vladmandic/human.git

# 2. servir a pasta human
cd human
npx serve                      # http://localhost:3000
# ou: python -m http.server 3000

# 3. abrir no Chrome
# http://localhost:3000/demo/video/

Turma inteira baixando no mesmo Wi-Fi: leve a pasta num pendrive.

Por que precisa de servidor?

Com duplo clique o endereço vira file:///... e o Chrome bloqueia o import da biblioteca:

Access to script at 'file:///.../human.esm.js'
from origin 'null' has been blocked by CORS policy

A câmera nem chega a ser pedida. Câmera e serial só funcionam em https:// ou em http://localhost, que o navegador trata como seguro.

Passo 1 · O laço de desenho é um game loop

  

    

      
1. pega o resultado mais recente
human.next()

      
2. pinta o quadro da webcam
human.draw.canvas(...)

      
4. agenda a próxima volta

3. desenha a detecção por cima

async function drawLoop() {
  const interpolated = human.next();
  human.draw.canvas(human.webcam.element, canvas);
  await human.draw.all(canvas, interpolated);
  setTimeout(drawLoop, 30);
}

      
A detecção roda em paralelo (linha 45, human.video(...)). O resultado bruto mais recente fica sempre em human.result. É de lá que vamos ler os pontos.

      
Qualquer coisa que a gente queira desenhar precisa entrar depois do draw.all, senão a imagem da webcam apaga.

Passo 2 · Contar piscada é tratar keydown / keyup

  

    

      
Errado: contar "olho fechado"

      
O olho fica fechado por vários quadros. Uma piscada viraria 3 ou 4 contagens, como contar quantas vezes o keydown repete com a tecla segurada.

      
Certo: contar a transição

      

        ABERTO
        abertura < limiar →
        FECHADO
      

      

        FECHADO
        abriu → +1 piscada →
        ABERTO
      

    

    
if (abertura < LIMIAR_PX) {
  olhoFechado = true;
} else if (olhoFechado) { // estava fechado e abriu
  piscadas++;
  olhoFechado = false;
}

Passo 3 · Dividir pela largura do próprio olho

  

    

      
Quando o rosto se aproxima, tudo cresce na mesma proporção.

      
razão = abertura / largura

perto:  20 px / 50 px = 0,40
longe:  10 px / 25 px = 0,40

      
Mesma ideia de usar % em vez de px num layout responsivo: o valor fica relativo ao tamanho do próprio elemento.

Passo 6 · Lado do micro:bit (MicroPython)

  

    
from microbit import *

IMAGENS = {
    "feliz": Image.HAPPY,    "triste": Image.SAD,
    "raiva": Image.ANGRY,    "surpresa": Image.SURPRISED,
    "medo": Image.CONFUSED,  "nojo": Image.SILLY,
    "neutro": Image.MEH,
}

uart.init(baudrate=115200)  # mesma velocidade do navegador
display.show(Image.ASLEEP)  # esperando a primeira mensagem
buffer = b""

while True:
    if uart.any():
        dados = uart.read()
        if dados:
            buffer += dados
        fim = buffer.find(b"\n")
        while fim != -1:  # pode ter chegado mais de uma linha
            linha = buffer[:fim]
            buffer = buffer[fim + 1:]
            texto = str(linha, "utf-8").strip()
            if texto in IMAGENS:
                display.show(IMAGENS[texto])
            fim = buffer.find(b"\n")
    sleep(10)

    

      
A UART começa em 9600; uart.init(115200) casa com o navegador.

      
Os bytes chegam aos pedaços: uma linha partida em dois read(), ou duas linhas juntas. Por isso o buffer e a busca pelo \n, como ler um stream de rede.
